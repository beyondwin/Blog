결론부터 말하면 **저장소의 기본 규칙은 `AGENTS.md`, 특정 작업의 절차와 도구는 Skill**에 두는 편이 현재 근거와 가장 잘 맞는다. Vercel의 Next.js 16 내부 평가에서는 문서 색인을 넣은 `AGENTS.md`가 100%를 기록했고 기본 Skill은 53%에 머물렀다. 하지만 이것은 모든 저장소와 모든 에이전트에서 `AGENTS.md`가 항상 우월하다는 증거가 아니다. 같은 보고서는 Skill을 명시적으로 호출하면 79%까지 오른다고 밝혔고, Vercel도 둘을 상호 보완적인 수단으로 설명한다.

이 글은 제공받은 HTML 보고서를 출발점으로 삼되, 수치와 동작은 Vercel 원문, AGENTS.md 공식 안내, Agent Skills 명세, OpenAI의 Skill 평가 방법, Next.js 공개 평가표, 최신 AGENTS.md 품질 연구와 대조했다.

## 먼저 알아야 할 개념

`AGENTS.md`는 저장소 안에 놓는 **항상 보이는 작업 안내서**다. 빌드 명령, 테스트 규칙, 디렉터리별 제약처럼 에이전트가 매 작업에서 알아야 할 정보를 담는다. 공식 안내에 따르면 하위 디렉터리에 별도 파일을 둘 수 있고, 작업 파일에 가까운 안내가 더 구체적인 규칙으로 적용된다.

Agent Skill은 `SKILL.md`를 중심으로 한 **필요할 때 불러오는 작업 묶음**이다. 시작할 때는 이름과 설명 같은 작은 메타데이터만 노출하고, 설명이 현재 요청과 맞을 때 본문과 부속 스크립트·참고 자료를 단계적으로 읽는다. 그래서 둘의 차이는 단순한 파일 형식이 아니라 전달 시점이다.

- `AGENTS.md`: 기본값, 금지 사항, 저장소 지도처럼 매번 필요한 문맥
- Skill: 배포, PDF 생성, 장애 조사처럼 조건부로 실행하는 절차와 도구

평가에서 중요한 것은 “정보가 존재하는가”뿐 아니라 **에이전트가 필요한 순간에 그 정보를 실제로 읽었는가**다.

## 실제 구조

Vercel은 Next.js 16 관련 질문을 에이전트가 해결하도록 네 조건을 비교했다.

| 조건 | 보고된 성공률 |
| --- | ---: |
| 추가 문서 없음 | 53% |
| Skill 제공, 별도 호출 지시 없음 | 53% |
| Skill을 명시적으로 사용하도록 지시 | 79% |
| 압축한 문서 색인을 `AGENTS.md`에 제공 | 100% |

보고서의 핵심 관찰은 기본 Skill 조건에서 **56%의 실행이 Skill을 호출하지 않았다**는 점이다. 반면 명시적 호출 지시가 있을 때 호출률은 95% 이상이었다. 즉 이 실험에서 차이를 만든 것은 문서 품질만이 아니라 발견 경로였다. `AGENTS.md`는 약 8KB의 압축 색인을 시작 문맥에 넣었고, Skill은 모델이 먼저 “이 Skill이 필요하다”고 판단해야 했다.

공개된 Next.js 평가표도 별도로 계산해 봤다. 2026년 7월 17일 표의 25개 조합에서 문서 제공 전 평균은 73.56%, 제공 후 평균은 89.64%로 16.08%포인트 올랐다. 23개 조합은 상승했고 2개는 같았으며 하락은 없었다. 다만 이 표는 **Next.js 문서 제공 전후**를 비교할 뿐, `AGENTS.md`와 Skill을 직접 겨루는 표는 아니다. Vercel 내부 실험의 100%를 독립 재현한 자료로 읽어서는 안 된다.

Agent Skills 명세도 반대편의 중요한 맥락을 준다. Skill은 시작 문맥을 작게 유지하고, 필요한 자료만 불러오는 구조다. OpenAI의 평가 가이드 역시 이름과 설명이 호출의 주된 신호이므로 “무엇을, 언제 쓰는지”를 구체적으로 쓰고, 명시·암시·맥락·음성 대조 프롬프트를 나눠 테스트하라고 권한다. 호출 실패는 Skill이라는 구조의 필연적 실패라기보다 발견성 설계와 평가 부족일 수 있다.

## 핵심 기능

두 방식을 함께 쓸 때 구조는 다음처럼 단순해진다.

1. 루트 `AGENTS.md`에는 런타임 버전, 기본 검증 명령, 보안 경계, 저장소 지도를 둔다.
2. 하위 `AGENTS.md`에는 그 디렉터리에서만 유효한 규칙을 둔다.
3. 반복 가능하지만 모든 작업에 필요하지 않은 절차는 Skill로 분리한다.
4. `AGENTS.md`에는 Skill의 이름을 나열하기보다 “어떤 상황에서 어떤 Skill을 사용한다”는 짧은 라우팅 규칙을 둔다.
5. 두 계층 모두 실제 프롬프트 묶음으로 호출률과 결과 품질을 평가한다.

이 구성이 좋은 이유는 상시 문맥의 확실성과 호출형 문맥의 경제성을 동시에 얻기 때문이다.

## 좋은 점

`AGENTS.md`의 강점은 실패 비용이 큰 기본 규칙을 우연한 호출에 맡기지 않는다는 데 있다. “테스트 전에 마이그레이션을 적용한다”, “개인 메모리는 공개 코드에서 읽지 않는다” 같은 규칙은 매번 보이는 편이 안전하다. 또한 일반 Markdown이라 여러 도구가 함께 사용할 수 있고, 디렉터리 계층으로 범위를 좁힐 수 있다.

Skill의 강점은 전문 절차를 상시 문맥에서 빼낼 수 있다는 점이다. 긴 배포 체크리스트, 브라우저 자동화 예제, 변환 스크립트까지 모든 요청에 넣으면 토큰만 쓰는 것이 아니라 관련 없는 지시가 현재 판단을 방해할 수 있다. Skill은 이런 자원을 필요할 때만 로드하고 실행 파일과 함께 배포할 수 있다.

따라서 “어느 파일이 더 세다”보다 **실패했을 때 큰 규칙은 상시 계층에, 드물고 긴 실행법은 호출 계층에 둔다**는 분류가 실무적으로 더 유용하다.

## 조심해야 할 점

가장 큰 사각지대는 `AGENTS.md`를 만능 해법으로 오해하는 것이다. 2026년 공개된 100개 인기 저장소 분석은 AGENTS/CLAUDE 지침에서 문맥 과다 42건, 린트 규칙 누출 62건, 초기 설정의 화석화 24건, 충돌 지시 28건 등을 보고했다. 연구의 일부 판정은 휴리스틱과 언어 모델에 의존하므로 숫자를 절대값으로 볼 수는 없지만, 긴 상시 지침이 새로운 실패를 만든다는 경고로는 충분하다.

실무에서 특히 확인할 항목은 다음과 같다.

- **문맥 과다**: 매번 필요하지 않은 튜토리얼과 예제를 상시 파일에 넣지 않았는가
- **규칙 누출**: formatter·linter가 이미 강제하는 세부 규칙을 자연어로 중복하지 않았는가
- **맹목적 참조**: 존재하지 않거나 권한 없는 파일을 “반드시 읽으라”고 하지 않았는가
- **화석화**: 생성 당시 버전·명령이 현재 저장소와 어긋나지 않았는가
- **충돌**: 루트와 하위 파일, Skill 사이에서 같은 행동을 다르게 요구하지 않는가

또 하나의 사각지대는 결과 지표다. 성공률 하나만 보면 비용, 지연, 토큰 사용량, 잘못된 Skill 호출, 지시 충돌을 놓친다. 저장소마다 실제 작업 표본을 만들고 정확도와 함께 호출률·불필요 호출률·비용을 측정해야 한다.

## 언제 쓰면 좋은가

`AGENTS.md`에 어울리는 것은 거의 모든 작업에 적용되는 작은 규칙이다. 빌드와 테스트 명령, 편집 가능 범위, 비밀정보 금지, 코드 스타일의 큰 원칙, 디렉터리별 소유권이 여기에 속한다.

Skill에 어울리는 것은 명확한 시작 조건과 끝 조건이 있는 절차다. 릴리스, 데이터 마이그레이션, 특정 문서 생성, 장애 증거 수집처럼 단계와 보조 자료가 길지만 호출 빈도가 낮은 작업이 그렇다.

둘 중 하나만 골라야 한다면 실패 비용으로 결정할 수 있다. 호출되지 않았을 때 바로 사고가 나는 규칙은 `AGENTS.md` 쪽에, 호출되지 않아도 평소 작업에는 영향이 없는 전문 절차는 Skill 쪽에 둔다.

## 주니어 개발자가 배울 점

첫째, 문서를 많이 쓰는 것과 좋은 문맥을 주는 것은 다르다. 좋은 지침은 짧고, 현재 저장소에서 실행 가능하며, 실패 조건이 분명하다.

둘째, AI 도구도 테스트해야 한다. “아마 읽겠지”가 아니라 자주 하는 요청, 애매한 요청, 사용하면 안 되는 요청을 각각 넣어 실제 호출 여부를 기록한다.

셋째, 벤치마크의 비교 대상을 정확히 읽어야 한다. Next.js 문서 제공 전후의 개선은 문서의 가치에 대한 근거지만, 모든 프로젝트에서 특정 전달 방식이 100%라는 증거는 아니다.

## 내 결론

`AGENTS.md` 대 Skill은 승자 독식 문제가 아니다. 현재 공개 근거가 지지하는 결론은 더 제한적이다. **중요한 기본 문맥은 상시 노출했을 때 안정적이고, Skill의 성패는 호출 설계에 크게 좌우된다.**

내가 새 저장소를 정리한다면 루트 `AGENTS.md`를 한 화면 안팎의 운영 계약으로 만들고, 긴 절차는 Skill로 분리하겠다. 그다음 10~20개의 실제 프롬프트로 “항상 필요한 규칙을 지켰는가”, “필요한 Skill을 불렀는가”, “필요 없을 때는 부르지 않았는가”를 측정하겠다. 100%라는 홍보 문구보다 이 저장소의 재현 가능한 평가가 최종 기준이어야 한다.
